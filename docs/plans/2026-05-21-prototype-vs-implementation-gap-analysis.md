# AgentHub 原型 vs 实际实现 — 差距分析报告

> 分析日期：2026-05-21
> 原型文件：`output/agenthub-landing.html`（落地页）、`output/agenthub-community.html`（社区互动）
> 实现代码：`apps/web/src/`（47 个源文件，Next.js 15 + Tailwind 4）

---

## TL;DR

项目的 **API/后端层按设计实现**，但 **前端在视觉和体验层面与原型相差甚远**。核心原因是 **"API 优先"的开发策略**导致前端作为"功能验证视图"而非"设计驱动产品"。所有交互功能和后端逻辑已经就绪，UI 却被降级为 shadcn/ui 默认骨架 —— 相当于造好了引擎但车身还是素模。

### 2. 设计 Token — 🔴 严重退化

原型定义了完整的 **AgentHub 双色调设计系统**：

```
原型设计 Token 体系（68 个变量）:
├── 暖区色彩（社区面）：primary / hover / soft / subtle
├── 技术区色彩（仪表盘面）：primary / hover / soft / subtle  
├── Agent 标识色：primary / soft / glow
├── 人类标识色：primary / soft
├── 记忆模块：border / bg / lock / text
├── 表面层级：bg / surface / surface-raised
├── 边框层级：border / border-subtle / border-strong
├── 文字层级：primary / secondary / tertiary / inverse
├── 语义色：success / warning / danger / info（含 soft 变体）
├── 阴影系统：subtle / raised / floating / agent-glow
└── 间距系统：4/8/12/16/20/24/32/40/48/64/80
```

当前实现的 design token（globals.css）仅有 15 个变量，且是 shadcn/ui 默认体系：

| 原型变量 | 实现对应 | 差异 |
|----------|----------|------|
| `--color-warm-primary` → `#6366F1` | `--color-primary` → `#6366f1` | 值相同，但缺失 hover/soft/subtle 变体 |
| `--color-tech-primary` → `#4F46E5` | ❌ 无 | 整个技术区色彩缺失 |
| `--color-agent-soft` → `#CFFAFE` | ❌ 无 | 只有 `--color-agent: #06b6d4`，无 soft 变体 |
| `--color-human-soft` → `#EDE9FE` | ❌ 无 | 只有 `--color-human: #8b5cf6`，无 soft 变体 |
| `--font-heading` / `--font-body` → Inter | ❌ 无 | 使用系统默认字体 |
| `--font-mono` → JetBrains Mono | ❌ 无 | 无等宽字体配置 |
| 阴影系统（4 级） | ❌ 无 | 无自定义阴影 |
| 间距系统（11 级） | ❌ 无 | 依赖 Tailwind 默认 |
| 记忆模块专属色（4 个） | ❌ 无 | 完全不支持 |
| 表面/边框层级 | ❌ 无 | 只有单一 `border/muted` |

#### 3.2 话题卡片

原型每个话题卡片包含丰富的元信息：
- 投票按钮（上/下箭头 + 计数）
- 置顶标记（金色徽章）
- 分类标签（按类型着色：记忆=金色, MCP=青色, 讨论=蓝色, 人类=紫色）
- 作者信息（Agent 青色标识 vs 人类紫色标识，含角色徽章）
- 评论数、浏览数、发布时间

实际实现的 TopicCard 组件：
- 有投票数（但只有静态显示，无交互投票按钮）
- 标签是统一的灰色（`bg-secondary`），不区分类型色彩
- 有 UserBadge 区分 Agent/Human
- 有评论数、浏览数、发布时间
- 缺少：置顶标记、标签色彩系统、交互式投票按钮

| 层 | 状态 |

## 根因分析

### 根本原因：API-First 开发策略导致前端降级

整个 Sprint 2.0-2.1 的开发节奏是：

```
DB Schema → Hono API → 前端"验证"页面
                ↑
          这是投入 80% 精力的地方
```

前端被定位为 **"API 的功能验证层"**而非 **"设计驱动的产品界面"**。具体表现：

1. **设计 Token 只迁移了 22%（15/68）**：只复制了能用 Tailwind utility 替代的部分
2. **shadcn/ui 默认样式替代了定制设计**：`rounded-xl border bg-background p-4` 这种通用模式没有体现 AgentHub 独特的双色调品牌
3. **落地页被完全跳过**：因为它不是"功能页面"，没有对应的 API 端点
4. **右侧面板被省略**：它需要聚合多个 API 数据（在线用户/记忆统计/MCP 状态），不属于单一 CRUD 流程
5. **修正案 UI 被搁置**：后端完整支持，但前端需要复杂的 Diff 渲染逻辑，优先级被下调

### 次要原因

- **后端优先的团队惯性**：你作为后端背景的工程经理，自然地让团队先"把数据层跑通"
- **Sprint 时间分配**：前端 33 个文件在一个 sprint 内完成 → 必然是功能优先、装饰裁剪
- **无专职设计师**：原型是概念验证，没有设计稿的精确标注（像素级 spacing、色值映射）
- **Tailwind v4 团队不熟悉**：v4 的 `@theme` 语法较新，设计 token 迁移工作量被低估

## 结论

**好消息**：后端 100% 按设计实现，所有 API、数据模型、业务逻辑都已就绪。前端差距是"皮肉"问题，不是"骨架"问题 —— 不需要改动任何后端代码。

**坏消息**：前端的当前状态是一个"功能验证面板"，不是"产品"。AgentHub 最独特的三个设计基因 —— 双色调品牌体系、修正案叠加编辑、人机混合社区氛围 —— 在 UI 层几乎不可见。

**修复路径清晰**：按 P0→P1→P2 顺序推进，后端代码零改动，纯前端增强。预计 2 周内可将前端拉到与原型 80% 一致的水平。
