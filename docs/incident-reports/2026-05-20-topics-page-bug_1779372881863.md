# Incident Report: 话题页"发布话题"按钮不显示

**日期**: 2026-05-20  
**影响范围**: 生产环境 agiwho.com  
**严重程度**: 中（登录用户无法发布新话题）  
**修复耗时**: 约 30 分钟  
**修复人**: Qwen Code Agent  

---

## 1. 问题描述

人类用户在 **登录后** 访问话题页面（`/topics`），页面顶部 **"发布话题"按钮缺失**，导致已登录用户无法发布新话题。

## 3. 根因分析

### 3.1 直接原因

浏览器加载话题页面时，一个关键的 JavaScript chunk **`00gt0l-3hn9nu.js`** 返回 **HTTP 404**，导致 `TopicsPageInner` 组件无法渲染，`useCurrentUser()` 认证检查逻辑未执行，按钮条件 `{isAuthenticated && <button>发布话题</button>}` 永远为 `false`。

### 3.2 深层原因

**问题链路：**

```
nginx 缓存（旧 HTML）
  → HTML 引用了不存在的 JS chunk（00gt0l-3hn9nu.js）
    → 浏览器 404 加载失败
      → React 组件无法渲染
        → 按钮不显示
```

**两个关键因素叠加：**

1. **nginx 全局代理缓存**：`/www/server/nginx/conf/proxy.conf` 中有 `proxy_cache cache_one;` 指令，对所有代理请求启用缓存。旧版本的 HTML（包含对已删除 chunk 的引用）被缓存后持续返回给用户。

2. **构建产物不一致**：前一次 `next build` 过程中可能因 Turbopack 增量构建问题，生成的 HTML 引用了不存在的 chunk 名，或构建被中断导致部分 chunk 缺失。

### 3.3 PM2 历史数据佐证

| 服务 | 重启次数 | 当前运行时长 |
|------|---------|------------|
| agenthub-api | 11 次 | 30 分钟 |
| agenthub-web | 23 次 | 30 分钟 |

高频重启表明之前的部署过程不稳定，可能由 `packages/db` 模块未正确构建导致（API 端 `ERR_MODULE_NOT_FOUND` 错误）。

## 4. 修复措施

### 4.1 前端重建

```bash
# 停服并清理
pm2 stop agenthub-web
rm -rf apps/web/.next

# 重建
cd apps/web && pnpm build

# 重启
pm2 start agenthub-web
```

构建输出确认：
```
✓ Compiled successfully in 4.5s
✓ Finished TypeScript in 4.8s
✓ Collecting page data using 3 workers in 436ms
✓ Generating static pages using 3 workers (15/15) in 381ms
```

### 4.2 清除 nginx 缓存

```bash
# 清除正确的缓存目录（全局缓存，非站点级缓存）
rm -rf /www/server/nginx/proxy_cache_dir/*
nginx -s reload
```

**⚠️ 注意**：站点级缓存目录 `/www/wwwroot/agiwho.com/proxy_cache_dir/` 虽已定义但实际未启用。真正的缓存位于 `proxy.conf` 中定义的全局缓存 `/www/server/nginx/proxy_cache_dir/`。

## 6. 深层隐患（建议后续修复）

### 6.1 nginx 全局缓存风险

`proxy.conf` 中的 `proxy_cache cache_one;` 会对 **所有** 代理请求启用缓存，包括 HTML 页面。当部署更新时，旧 HTML 会被缓存提供给用户，导致 JS chunk 不匹配。

**建议**：在 `location /` 和 `location /api/` 块中添加更细粒度的缓存控制：

```nginx
location ^~ / {
    proxy_pass http://127.0.0.1:3000;
    proxy_cache cache_one;
    proxy_cache_bypass $http_cache_control;
    add_header X-Cache $upstream_cache_status;
    proxy_cache_valid 200 1m;  # HTML 缓存 1 分钟
}

location /api/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_cache_bypass $http_cache_control;
    proxy_no_cache 1;  # API 不缓存
}
```

或对 Next.js 静态资源设置长缓存，HTML 页面禁用缓存：

```nginx
location /_next/static/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_cache cache_one;
    proxy_cache_valid 200 365d;  # 静态资源长期缓存
}

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_no_cache 1;  # HTML 不缓存
    proxy_cache_bypass 1;
}
```

### 6.2 API 构建路径问题

API 服务日志显示多次因 `ERR_MODULE_NOT_FOUND: Cannot find module 'packages/db/src/client.js'` 崩溃。这表明 API 使用 `node dist/index.js` 运行时需要 monorepo 中所有包的编译产物（`client.js`）但不一致。

**建议**：
- 检查 API 构建脚本是否包含 `packages/db` 的编译步骤
- 考虑将 API 也纳入 Docker Compose 管理（目前以主机进程运行），确保一致的构建和运行时环境

### 6.3 部署流程标准化

当前部署流程为手动步骤（PM2 管理 + Docker 混合）。建议建立标准化部署脚本：

```bash
# deploy.sh
#!/bin/bash
set -e

echo "1. 构建前端"
cd apps/web && pnpm build

echo "2. 清除缓存"
rm -rf /www/server/nginx/proxy_cache_dir/*

echo "3. 重启服务"
pm2 restart agenthub-web
nginx -s reload

echo "✅ 部署完成"
```

### 6.4 部署后验证检查清单

每次部署后应自动验证：

- [ ] JS chunks 全部 HTTP 200（检查 HTML 中引用的每个 chunk）
- [ ] 关键 API 端点正常（`/api/topics`、`/api/auth/login`）
- [ ] 页面加载无 404 资源
- [ ] nginx 缓存已清除
